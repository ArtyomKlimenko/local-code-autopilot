# Local Code: веб-интерфейс

Открыть: http://127.0.0.1:8766/

После перезагрузки компьютера найдите **Local Code** в меню «Пуск».
Ярлык запускает локальный сервер скрыто и открывает браузер. Команда
local-code-ui делает то же самое. Держать CMD открытым не требуется.
Планировщик Windows используется только для запуска по запросу с обычными
правами пользователя; периодического мониторинга и облачного агента нет.

## Новая задача

1. Нажмите «Новая задача».
2. Вставьте весь промпт в поле «Задача». Русский и переносы строк поддерживаются.
3. Укажите локальную папку: она будет домом плана, задач и состояния.
4. Укажите SSH-адрес и папку кода на Debian VM. Путь к ключу передаётся
   OpenSSH; содержимое ключа интерфейс не читает.
5. Выберите контекст и размышления, нажмите «Создать задачу», затем «Запустить».

Первый проход создаёт локальный план; затем существующий supervisor запускает
исполнителя и проверяющего по шагам. Новый интерфейс не меняет правила
планирования или ограничения доступа агента.

## Во время работы

- «Ход работы»: текущий проход, текст модели, разворачиваемые рассуждения,
  команды и результаты. Фильтры позволяют оставить команды или ошибки.
- «План»: шаги, критерии готовности, замечания проверяющего и прогресс.
- «Задача»: исходный промпт. Правка доступна до создания плана.
- «Журнал»: результаты, принятые проверяющим.
- Поле под историей: уточнение агенту. Оно сохраняется локально, передаётся
  через Pi RPC steer и включается в контекст следующих проходов. Статусы
  «В очереди Pi», «Получено агентом» и «Включено в контекст» различаются.
- «Остановить»: штатный запрос остановки supervisor; «Продолжить» запускает
  ту же задачу с сохранённым состоянием.
- Если шаг требует разрешения, интерфейс показывает его формулировку и
  отдельную кнопку разрешения. Если нужны данные или действие пользователя,
  отображается USER_ACTION_REQUIRED.md.
- «В архив» скрывает задачу из основного списка, сохраняя все файлы. Задачу
  можно восстановить из «Архива задач».

Закрытие страницы не останавливает агент. После повторного открытия
восстанавливаются состояние и последняя история. Вручную запущенные через CLI
задачи тоже видны, если их папка добавлена в интерфейс.

## Модель

Запуск проходит через существующий GPU-only launcher. Полный offload и
Vulkan KV-cache проверяются до начала агента. Зелёный статус GPU требует
подтверждения именно текущего процесса по PID и времени запуска, а не просто
старого лога. При смене контекста модель перезапускается тем же launcher.
Большие значения контекста в меню не означают, что они гарантированно
поместятся в конкретную GPU: ошибка загрузки выводится прямо в интерфейсе.

Одновременно запускается одна coding-задача. Это соответствует одному слоту
локального сервера и не допускает конкурирующих запусков через UI.

## Устройство и установка

Frontend: Preact, lucide-preact, markdown-it и DOMPurify. Компоненты сообщений
адаптированы из открытого Pi Web UI; лицензия и точная ревизия находятся в
src/web/THIRD_PARTY.md. Backend: стандартные модули Node.js. Electron,
дополнительная модель, база данных и runtime npm-зависимости не требуются.
После сборки npm и Vite при обычном запуске не используются.

Веб-сервер слушает только 127.0.0.1, проверяет Host/Origin и токен
изменяющих запросов. Скрипты и стили собраны локально, CDN и телеметрии нет.
Это интерфейс доверенного локального пользователя, а не многопользовательский
сервер для публикации в интернете.

Сборка и проверки из папки src/web:

    npm ci
    npm test
    npm run build

Установка из корня репозитория после установки GPU launcher и supervisor этой
версии:

    powershell -File scripts/install-web.ps1 -ProjectsRoot C:\work

Установленные файлы UI: C:\LocalAI\webui.
Список проектов и журнал сервера: C:\LocalAI\state\web.
Каждая задача сохраняет уточнения, квитанции доставки и журнал запуска в своей
локальной .agent. Исходные GOAL.md/PLAN.md/tasks.json остаются источником
состояния; отдельной копии плана в браузере нет.

История читается по смещению в файле, с сохранением неполных строк и UTF-8.
При открытии большого прохода загружается его последний фрагмент, а дальше
только новые байты. Предыдущие проходы выбираются в списке истории.

и текущую роль, но сам по себе не устраняет ошибки принятия решений модели.
